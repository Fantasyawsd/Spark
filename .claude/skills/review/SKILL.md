# /review 代码审查

由人类编排者在 `/test` 通过后、`/finish` 前触发。只读审查，不修改被审查文件。审查出的阻断项回到 `/develop` 修复。

## 步骤

1. **确认审查范围**
   - 读 status.md 明确目标、验收标准与非目标；确认 diff 范围（从 `origin/main` merge-base 起）。
   - 完成标准：diff 范围与任务规格明确。

2. **只读核对结构**
   - 不修改任何文件；逐条对照 `docs/standards/code-structure.md`「提交前结构检查清单」与「代码审查阻断条件」核对改动。
   - 完成标准：每个改动文件都被检查；每条阻断条件判定为触发/未触发。

3. **对照规格**
   - 检查改动是否达成任务目标与每项验收标准、是否引入非目标改动；改动范围一致性见 `AGENTS.md`「架构与代码原则」。
   - 完成标准：每项验收标准有满足 / 未满足 / 证据不足的结论。

4. **输出审查报告**
   - 按 `references/review-report.md` 模板，按严重度（阻断 / 缺陷 / 建议）列出问题，给出文件与行号与修复方向；不做大范围重写。
   - 完成标准：报告含严重度、位置、修复方向。

5. **写入台账并汇报**
   - 将报告摘要（阻断项与缺陷）写入 status.md；完整报告呈现给编排者，是否修复由编排者决定。
   - 完成标准：台账已记录审查结论；阻断项是否必须修复已明确。
