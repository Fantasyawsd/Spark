## 维护规则

1. 跨版本原则、长期路线和稳定架构决策写入总文档。
2. 具体功能必须先确定目标版本，再写入对应的 `versions/<version>/` 目录。
3. 发布计划、进度审计、验收清单和版本内设计不得散落在 `docs/` 根目录。
4. 已发布版本的文档只补充勘误和最终证据，不用后续版本计划覆盖历史状态。
5. 文件名和链接使用真实语义版本号，不再使用含义不清的 `v1`、`next` 或 `latest`。
6. 功能状态统一使用“规划中、开发中、已完成、已延期、已取消”，并说明证据或延期目标版本。
