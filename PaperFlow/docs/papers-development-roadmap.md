# PaperFlow 论文页开发路线

> 状态：规划中  
> 最近更新：2026-07-31  
> 适用范围：`lib/src/features/papers/`

## 1. 文档目标

本文记录 PaperFlow 论文页在完成 UI 原型后的功能缺口、技术边界、开发优先级和验收标准。

当前论文页已经具备完整的视觉和本地演示交互，但核心数据仍来自 Demo，搜索、分类、分享、评论、用户关系和持久化尚未形成真实业务闭环。后续开发应保留现有 Flutter UI 和交互结构，逐步替换本地模拟实现，不在页面组件中继续堆叠业务逻辑。

## 3. 当前实现边界

### 3.1 数据源

`PaperRepository` 当前只有同步的 `getAll()`，实际实现返回固定 Demo 数据：

```dart
abstract interface class PaperRepository {
  List<PaperRecord> getAll();
}
```

因此当前不支持：

- 远程论文数据
- 分页
- 刷新
- 加载状态
- 空状态
- 网络错误和重试
- 本地缓存

### 3.2 页面状态

`PaperController` 当前同时管理：

- 当前论文索引
- 单页和双栏模式
- 当前分类
- 自定义主题
- 点赞状态
- 收藏状态

其中点赞、收藏和自定义主题只存在内存中，应用重启后会丢失。

### 3.3 可见但尚未生效的入口

- 搜索按钮回调为空。
- 分享按钮回调为空。
- 分类切换只改变选中索引，不过滤论文。
- “关注”没有作者、主题或会议关注数据。
- 相关论文是 Markdown 文本，不能打开对应论文。
- 评论中的“回复”只是静态文字。
- AI 分析区部分工具图标没有行为。
- 语音输入图标没有语音能力。

### 3.4 DeepSeek

DeepSeek 请求代码已经存在，但仍属于开发接入状态：

- API Key 通过 `--dart-define` 编译进客户端。
- 回复不是流式输出。
- 会话只存在当前 Bottom Sheet 中。
- 关闭 Sheet 后对话丢失。
- 没有请求取消、重试、限流和额度控制。
- AI 上下文只有论文元信息和摘要，不包含全文、图表或参考文献。

正式发布时不能将 DeepSeek API Key 放在 APK 中，应通过 PaperFlow 后端代理请求。

## 4. P0 必须实现

### 4.1 真实论文数据源

目标：用可异步加载的数据层替换固定 Demo 列表。

建议接口：

```dart
abstract interface class PaperRepository {
  Future<PaperPage> getPapers({
    String? category,
    String? query,
    String? cursor,
  });

  Future<PaperRecord> getPaper(String paperId);
}
```

待实现：

- [ ] 论文列表接口
- [ ] 论文详情接口
- [ ] 游标或页码分页
- [ ] 接近列表末尾时预加载
- [ ] 下拉刷新
- [ ] 首次加载状态
- [ ] 下一页加载状态
- [ ] 空数据状态
- [ ] 网络错误和重试
- [ ] 本地缓存和离线回退
- [ ] Demo Repository 保留用于测试和预览

验收标准：

- 网络正常时可连续浏览多页论文。
- 请求失败不会导致页面空白或崩溃。
- 重试成功后保留当前页面位置。
- 重启应用后可以展示最近缓存的论文。

### 4.2 分类和关注真实生效

当前分类只更新选中状态。需要定义每个分类的业务语义：

| 分类 | 目标行为 |
| --- | --- |
| 推荐 | 获取个性化或默认推荐流 |
| 关注 | 展示已关注作者、会议和主题的论文 |
| NLP | 筛选自然语言处理论文 |
| CV | 筛选计算机视觉论文 |
| ML | 筛选机器学习论文 |
| 自定义主题 | 按用户选择的主题筛选 |

待实现：

- [ ] 分类与请求参数映射
- [ ] 分类切换后刷新论文列表
- [ ] 每个分类保存独立列表和滚动位置
- [ ] 自定义主题本地持久化
- [ ] 关注作者
- [ ] 关注会议
- [ ] 关注主题
- [ ] 取消关注
- [ ] 关注页空状态

## 7. 推荐架构调整

### 7.1 数据层

建议拆分：

```text
PaperRepository
  |- PaperRemoteDataSource
  |- PaperLocalDataSource
  `- PaperCache

CommentRepository
InteractionRepository
FollowRepository
PaperAiService
```

Repository 对上层只暴露领域对象，不让 UI 直接处理 HTTP、JSON 或数据库记录。

### 7.2 状态层

不要把后续功能全部加入现有 `PaperController`。建议按职责拆分：

```text
PaperFeedController
  - 分类论文流
  - 分页
  - 刷新
  - 当前论文

PaperInteractionController
  - 点赞
  - 收藏
  - 分享

PaperSearchController
  - 查询
  - 历史
  - 搜索结果

PaperDetailController
  - 详情
  - PDF
  - 相关论文
```

评论和 AI 可以继续拥有独立状态，不应依附论文 Feed 的生命周期。

### 7.3 领域模型

建议将列表摘要与完整详情分开，避免论文流一次加载大量全文：

```text
PaperSummary
  - 信息流必需字段

PaperDetail
  - 摘要、全文、作者、引用、资源链接

PaperInteractionState
  - 点赞、收藏、评论计数
```

## 8. 分阶段开发顺序

### 阶段一：本地功能闭环

- [ ] 本地搜索

- [ ] 系统分享
- [ ] 点赞和收藏本地持久化
- [ ] 自定义主题持久化

交付标准：所有论文页可见入口都有真实行为，应用重启后本地状态不丢失。

### 阶段二：远程数据闭环

- [ ] 用户登录
- [ ] 论文列表和详情接口
- [ ] 分页和刷新
- [ ] 评论接口
- [ ] 点赞和收藏同步

- [ ] 分享深链接

交付标准：论文页不再依赖 Demo 数据，主要业务状态可跨设备同步。

### 阶段三：深度阅读

- [ ] PDF 下载和阅读

- [ ] 公式、图表和参考文献
- [ ] 引用关系

交付标准：用户可以从发现论文进入完整阅读和资料获取流程。

### 阶段四：AI 生产化

- [ ] 后端代理 DeepSeek

交付标准：密钥安全、结果可追溯、会话可恢复、成本可控制。

## 9. 第一轮建议任务

第一轮建议优先解决当前界面上最明显的空功能：

1. 实现本地搜索和分类过滤。
2. 接入系统分享。
3. 持久化点赞、收藏和自定义主题。
4. 将相关论文改为可点击结构化数据。
5. 为上述功能补充 Controller 单元测试和 Widget 测试。

完成后，论文页将从纯 UI Demo 进入可离线使用的本地产品阶段，并为后续远程接口迁移建立稳定边界。

## 10. 测试与验收要求

每项功能至少覆盖：

- 正常流程
- 空数据
- 加载中
- 请求失败
- 重试
- 重复点击
- 页面切换后的状态恢复
- 应用重启后的持久化恢复
- Android 小屏和常见屏幕尺寸
- 系统减少动画设置

每个阶段完成后执行：

```text
flutter analyze
flutter test
flutter build apk --debug
flutter build windows --release
```

视觉验收继续以 Android 手机为主要平台，Windows 用于快速检查和回归构建。
