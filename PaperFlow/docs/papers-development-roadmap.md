# PaperFlow 论文页开发路线

> 状态：规划中  
> 最近更新：2026-07-31  
> 适用范围：`lib/src/features/papers/`

## 1. 文档目标

本文记录 PaperFlow 论文页在完成 UI 原型后的功能缺口、技术边界、开发优先级和验收标准。

当前论文页已经具备完整的视觉和本地演示交互，但核心数据仍来自 Demo，搜索、分类、分享、评论、用户关系和持久化尚未形成真实业务闭环。后续开发应保留现有 Flutter UI 和交互结构，逐步替换本地模拟实现，不在页面组件中继续堆叠业务逻辑。

### 核心开发原则

本项目采用“本地功能先行，数据库后接入”的顺序：

1. 先使用现有 Demo 论文数据完成所有可见功能。
2. 分类、搜索、点赞、收藏、评论、转发和 AI 必须先在本地形成完整交互闭环。
3. 需要保留的状态先写入本地存储，不等待用户系统或远程数据库。
4. UI 只依赖 Repository、Service 和 Controller 接口，不直接依赖本地文件或远程 API。
5. 本地功能验收通过后，再将 Repository 的本地实现替换为数据库和服务端实现。

数据库不是第一阶段的前置条件。第一阶段的目标是让当前界面中的每个按钮都有真实、可测试的行为。

## 3. 当前实现边界

### 3.1 数据源

`PaperRepository` 当前只有同步的 `getAll()`，实际实现返回固定 Demo 数据：

```dart
abstract interface class PaperRepository {
  List<PaperRecord> getAll();
}
```

因此当前不支持：

- 远程论文数据
- 分页
- 刷新
- 加载状态
- 空状态
- 网络错误和重试
- 本地缓存

### 3.2 页面状态

`PaperController` 当前同时管理：

- 当前论文索引
- 单页和双栏模式
- 当前分类
- 自定义主题
- 点赞状态
- 收藏状态

其中点赞、收藏和自定义主题只存在内存中，应用重启后会丢失。

### 3.3 可见但尚未生效的入口

- 搜索按钮回调为空。
- 分享按钮回调为空。
- 分类切换只改变选中索引，不过滤论文。
- “关注”没有作者、主题或会议关注数据。
- 相关论文是 Markdown 文本，不能打开对应论文。
- 评论中的“回复”只是静态文字。
- AI 分析区部分工具图标没有行为。
- 语音输入图标没有语音能力。

### 3.4 DeepSeek

DeepSeek 请求代码已经存在，但仍属于开发接入状态：

- API Key 通过 `--dart-define` 编译进客户端。
- 回复不是流式输出。
- 会话只存在当前 Bottom Sheet 中。
- 关闭 Sheet 后对话丢失。
- 没有请求取消、重试、限流和额度控制。
- AI 上下文只有论文元信息和摘要，不包含全文、图表或参考文献。

正式发布时不能将 DeepSeek API Key 放在 APK 中，应通过 PaperFlow 后端代理请求。

## 4. P0 本地功能闭环

P0 不接数据库，继续使用 Demo 论文数据。所有状态先由本地 Repository 管理，需要跨重启保留的内容写入本地存储。

### 4.1 本地数据和状态接口

先建立稳定接口，避免后续接数据库时修改 UI：

```text
PaperRepository          读取 Demo 论文和本地筛选
InteractionRepository    点赞、收藏和计数
CommentRepository        评论、回复和评论点赞
PreferenceRepository     自定义主题和搜索历史
ShareService             调用系统分享
PaperAiService           调用 DeepSeek
```

待实现：

- [ ] UI 不直接读写本地存储
- [ ] Repository 提供内存实现用于测试
- [ ] Repository 提供本地持久化实现用于应用
- [ ] 所有领域对象使用稳定的论文 ID 关联
- [ ] 本地读写失败时返回可处理的错误

### 4.2 本地分类

分类直接过滤当前 Demo 论文，不请求网络：

| 分类 | 本地行为 |
| --- | --- |
| 推荐 | 展示全部 Demo 论文，保留当前顺序 |
| 关注 | 展示本地标记为关注的论文或主题 |
| NLP | 根据论文主题字段筛选 NLP 论文 |
| CV | 根据论文主题字段筛选 CV 论文 |
| ML | 根据论文主题字段筛选 ML 论文 |
| 自定义主题 | 根据用户选择的主题筛选 |

待实现：

- [ ] 为 Demo 论文补充明确的领域分类字段
- [ ] 分类切换后立即更新单页和双栏列表
- [ ] 空分类显示空状态
- [ ] 每个分类保存当前论文位置
- [ ] 自定义主题写入本地存储
- [ ] 本地关注和取消关注
- [ ] 关注页只展示本地关注内容

验收标准：切换任何分类都会改变实际论文列表，而不只是改变 Tab 颜色。

## 8. 推荐架构调整

### 8.1 数据层

建议拆分：

```text
PaperRepository
  |- PaperRemoteDataSource
  |- PaperLocalDataSource
  `- PaperCache

CommentRepository
InteractionRepository
FollowRepository
PaperAiService
```

Repository 对上层只暴露领域对象，不让 UI 直接处理 HTTP、JSON 或数据库记录。

### 8.2 状态层

不要把后续功能全部加入现有 `PaperController`。建议按职责拆分：

```text
PaperFeedController
  - 分类论文流
  - 分页
  - 刷新
  - 当前论文

PaperInteractionController
  - 点赞
  - 收藏
  - 分享

PaperSearchController
  - 查询
  - 历史
  - 搜索结果

PaperDetailController
  - 详情
  - PDF
  - 相关论文
```

评论和 AI 可以继续拥有独立状态，不应依附论文 Feed 的生命周期。

### 8.3 领域模型

建议将列表摘要与完整详情分开，避免论文流一次加载大量全文：

```text
PaperSummary
  - 信息流必需字段

PaperDetail
  - 摘要、全文、作者、引用、资源链接

PaperInteractionState
  - 点赞、收藏、评论计数
```

## 10. 第一轮建议任务

第一轮只开发本地功能，不接数据库：

1. 为 Demo 论文补充分类字段，实现分类过滤。
2. 实现本地搜索、结果打开和搜索历史。
3. 持久化点赞、收藏和自定义主题。
4. 实现本地评论、回复和评论点赞。
5. 接入 Android 系统分享面板。
6. 完善 DeepSeek 重试、取消和会话管理。
7. 为上述功能补充 Repository、Controller 和 Widget 测试。

完成后，论文页将从纯 UI Demo 进入本地可用产品阶段。数据库开发从第二阶段开始，并通过替换 Repository 实现接入。
