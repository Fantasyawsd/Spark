# PaperFlow 开发总路线

> 状态：持续维护
> 最近更新：2026-08-02

本文只维护 PaperFlow 的跨领域目标、优先级和依赖关系。具体需求、实现状态和验收标准归入 `product/<domain>/`；发布范围和发布证据只归入 `releases/<version>/`。

## 1. 产品边界

PaperFlow 面向个人研究者，核心闭环由三个一级能力组成：

1. **论文**：发现、筛选、阅读、收藏和管理论文。
2. **ChatPaper**：围绕通用问题或指定论文进行可恢复的 AI 对话。
3. **我的**：管理个人研究数据、收藏分组、阅读记录、主题和 DeepSeek 凭据。

社区、私信、通知、账号体系、云同步和内容发布暂不进入当前生产导航。它们只有在重新确认产品价值、数据来源和维护成本后才建立独立领域文档。

## 2. 持续优先级

### P0：单机可用与发布质量

- 保证论文、ChatPaper、我的三个入口形成完整单机闭环。
- 保证本地数据可恢复、可清理、可迁移，密钥不进入源码和公开构建。
- 保持 Android 构建、关键 Widget 测试和发布清单可重复执行。

### P1：论文发现与结构化阅读

- 将推荐、关注、最新和用户频道统一为可扩展频道模型。
- 补齐 arXiv Subject、发布时间、会议、Track、作者与单位等结构化元数据。
- 建立 Abstract、摘要、关键词、作者与单位、AI 解读、相关论文的阅读信息架构。
- 按需下载 PDF，生成可缓存的六问 AI 解读。

### P2：ChatPaper 研究工作流

- 统一主聊天与论文聊天的数据模型、上下文边界和恢复行为。
- 提升流式 Markdown、公式、代码和来源展示的稳定性。
- 为未来服务端代理、共享派生数据和成本控制保留接口边界。

### P3：个人研究资料管理

- 完善收藏分组、阅读历史、稍后阅读、数据统计和清理流程。
- 为导入导出、备份恢复和后续账号同步建立稳定的领域契约。

## 4. 工程依赖

- 架构与代码边界遵守[代码结构原则](standards/code-structure.md)。
- 分支、worktree、提交和集成遵守[Git 与多 Agent 集成管理](standards/version-control.md)。
- 并行任务通过 `workstreams/<branch-slug>/status.md` 和 `report.md` 交换状态，不通过共享未提交文件协作。
- 远程论文、AI、持久化和平台能力通过抽象接口接入，不进入 Widget 或领域实体。

## 5. 发布关系

开发任务默认不绑定版本。只有当一组已经实现并验证的能力被选入发布候选后，才在 `releases/<version>/` 建立或更新：

- 发布范围；
- 发布计划；
- 发布检查清单；
- 进度与风险审计；
- 隐私、许可和签名资料。

当前发布资料见 [0.1.0 发布归档](releases/0.1.0/README.md)。发布归档记录历史事实，不反向成为日常功能开发的唯一入口。
