# PaperFlow 开发计划

> 状态：持续维护
> 最近更新：2026-08-04

本文是开发计划的唯一文件，涵盖产品边界、优先级和各领域（论文 / ChatPaper / 我的）的能力现状与未来方向。发布范围和发布证据归入 `releases/<version>/`；架构、Git 与发布规则分别见 [`standards/code-structure.md`](standards/code-structure.md)、[`standards/version-control.md`](standards/version-control.md)、[`standards/release-management.md`](standards/release-management.md)。

## 1. 产品边界与优先级

### 1.1 产品边界

PaperFlow 面向个人研究者，核心闭环由三个一级能力组成：

1. **论文**：发现、筛选、阅读、收藏和管理论文。
2. **ChatPaper**：围绕通用问题或指定论文进行可恢复的 AI 对话。
3. **我的**：管理个人研究数据、收藏分组、阅读记录、主题和 DeepSeek 凭据。

社区与私信作为未来扩展功能保留（见第 5 节），当前阶段不进入生产导航。通知、账号体系、云同步和内容发布暂不进入当前生产导航，它们只有在重新确认产品价值、数据来源和维护成本后才纳入规划。

### 1.2 持续优先级

#### P0：单机可用与发布质量

- 保证论文、ChatPaper、我的三个入口形成完整单机闭环。
- 保证本地数据可恢复、可清理、可迁移，密钥不进入源码和公开构建。
- 保持 Android 构建、关键 Widget 测试和发布清单可重复执行。

#### P1：论文发现与结构化阅读

- 将推荐、关注、最新和用户频道统一为可扩展频道模型。
- 补齐 arXiv Subject、发布时间、会议、Track、作者与单位等结构化元数据。
- 建立 Abstract、摘要、关键词、作者与单位、AI 解读、相关论文的阅读信息架构。
- 按需下载 PDF，生成可缓存的六问 AI 解读。

#### P2：ChatPaper 研究工作流

- 统一主聊天与论文聊天的数据模型、上下文边界和恢复行为。
- 提升流式 Markdown、公式、代码和来源展示的稳定性。
- 为未来服务端代理、共享派生数据和成本控制保留接口边界。

#### P3：个人研究资料管理

- 完善收藏分组、阅读历史、稍后阅读、数据统计和清理流程。
- 为导入导出、备份恢复和后续账号同步建立稳定的领域契约。

## 2. 论文

### 2.1 当前能力

- 论文、ChatPaper、我的三个一级页面，本地功能形成完整单机闭环。
- 正式组合根接入 arXiv Atom 远程目录、版本化论文缓存与离线回退，内置种子保证冷启动。
- 结构化频道体系：推荐 / 关注 / 最新固定频道 + 用户主题频道（首批 cs.AI / cs.CL / cs.CV / cs.LG），频道栏与「主题 / 会议」Tab 管理页已上线；频道偏好版本化持久化，每频道独立论文列表、浏览位置与懒加载。
- 论文元数据语义已拆分（source / venue / journalReference / comment / affiliations / subjects），未知单位与未知引用数不再显示占位数据；生产 arXiv 链路不产生引用数，展示入口保留待接入可靠引用来源。
- 本地搜索、点赞、收藏、评论、分享、阅读历史、稍后阅读和自定义收藏分组已持久化；搜索框支持 arXiv ID / abs / PDF 链接直达论文。
- DeepSeek BYOK 流式翻译与对话；密钥存设备安全存储，公开构建不含共享 Key。
- 论文与 ChatPaper 共用 Markdown 渲染路径已支持真正的行内 LaTeX：公式、前后正文和标点保持同一段排版；论文 Abstract 通过选择区域保持文本可选，AI 内容继续支持不可选模式。
- 主要 UI 流程有 Widget 测试覆盖，Android debug APK 可重复构建。

### 2.2 当前边界

- 无账号、无跨设备同步、无服务端代理；关注、收藏、评论等均为本地状态。
- 相关论文使用结构化本地关系，未接入真实引用图谱。
- AI 上下文只有论文元信息与摘要，不含全文、图表或参考文献。
- 远程导入与同步适配器已提供；完整快照、论文库与服务端 PaperStore 属于服务端阶段。

### 2.3 后续方向

#### 频道、索引与阅读

- 统一推荐、关注、最新、用户主题与会议频道模型。
- 补齐 arXiv 结构化元数据、会议目录与时间筛选。
- 六页阅读结构（Abstract / 摘要 / 关键词 / 作者与单位 / AI 解读 / 相关论文）。
- PDF 下载、文本提取与六问 AI 解读，作为论文 ChatPaper 默认上下文。

#### 服务端与数据闭环

- 用户登录，点赞、收藏、评论、关注与搜索历史同步，本地未同步操作队列。
- DeepSeek 后端代理：安全保存 Key、额度、限流、会话云持久化与成本控制。
- 论文级共享派生数据：中文摘要、关键词、AI 解读、PDF 解析与语义向量的云端缓存。
- arXiv 完整快照与增量同步、论文库接入。

#### 深度功能与推荐

- 结构化作者与机构、关键词、BibTeX、参考文献与引用关系。
- 推荐系统利用阅读、停留、互动与关注信号，支持去重、排除已读和推荐原因。

### 2.4 频道、索引与阅读计划

当前规划借鉴 Cool Papers 的可组合论文索引和内容发现方式，但不复制其桌面端密集列表。PaperFlow 继续以 Android 手机信息流为主，重点解决频道扩展、论文元数据语义、内容关键词和深度 AI 解读。

当前范围暂不实现引用数、跨用户热度、全量 BM25 搜索、引用图谱和云端共享结果。没有真实数据源的会议频道不得以 Demo 数据进入生产入口。

#### 顶部论文频道

顶部所有频道使用与“推荐 / 关注 / 最新”一致的文字加下划线样式：

```text
推荐  关注  最新  人工智能  计算与语言  机器学习  ICML  ACL  ＋
```

- `推荐 / 关注 / 最新` 固定存在，不能删除。
- 用户添加的主题和会议显示在后面。
- 频道栏支持横向滚动。
- `＋` 固定在右侧，始终可见。
- 每个频道独立保存浏览位置。
- 点击论文后仍进入当前频道对应的信息流。
- 不再使用原来的领域筛选按钮。

#### 添加频道

点击 `＋` 打开频道管理页，分为两个部分。

**按主题**：名称使用中文，内部保留真实 arXiv 分类编号：

| 显示名称 | arXiv 分类 |
| --- | --- |
| 人工智能 | `cs.AI` |
| 计算与语言 | `cs.CL` |
| 计算机视觉与模式识别 | `cs.CV` |
| 机器学习 | `cs.LG` |

以后可以继续加入机器人、信息检索、计算机安全、分布式系统等官方 arXiv 分类。

**按会议**：会议名称保留官方缩写：

```text
AAAI             ACL              COLM
COLT             CoRL             CVPR
ECCV             EMNLP            ICCV
ICLR             ICML             IJCAI
INTERSPEECH      IWSLT            MICCAI
MLSYS            NAACL            NDSS
NeurIPS          OSDI             UAI
USENIX-Fast      USENIX-Sec
```

频道管理需要支持：

- 添加和移除频道。（已完成，对勾即添加状态）
- 搜索主题或会议。（暂缓：目录仅 4 个主题时搜索无价值，目录扩大后恢复）
- 调整频道顺序。（暂缓：当前按目录顺序展示，数据层已保留顺序能力）
- 已添加状态清晰可见。（已完成）
- 本地持久化。（已完成，`papers.channel-preferences` 版本化存储）

会议频道必须接入真实会议数据源后再进入正式版本，不能只提供空白 UI。

#### 时间筛选

原来的筛选按钮改成时间筛选，不再负责领域分类：

```text
不限时间
最新发布日
最近 7 天
最近 30 天
选择日期
自定义时间范围
```

时间筛选只作用于当前频道，例如：

```text
机器学习 + 最近 7 天
ACL + 2026 年
ICML + 2025 年
```

会议数据还可以进一步按年份和 Track 筛选。

#### 论文索引信息

**arXiv 主题论文**必须具备：

- arXiv ID
- 标题
- 作者
- Abstract
- Subjects
- Publish Time
- 更新时间
- 原始论文地址
- PDF 地址

Subjects 示例：

```text
Machine Learning (cs.LG)
Artificial Intelligence (cs.AI)
Computation and Language (cs.CL)
```

**会议论文**必须具备：

- 标题
- 作者
- Abstract
- 会议名称
- 会议年份
- Track 或论文类型
- 原始来源
- PDF 地址

Subject 使用结构化格式：

```text
ACL 2026 · Long Paper
ICML 2026 · Oral
CVPR 2026 · Highlight
NeurIPS 2025 · Poster
```

**暂缓引用数**：引用数暂不以不可靠数据出现在产品界面。

- 当前实现：引用数为可空未知语义，未知不显示；生产 arXiv 链路不产生引用数；展示入口保留。
- arXiv 本身不提供可靠引用数。
- 未增强的数据不能显示成“被引 0”。
- 后续接入 OpenAlex 或 Semantic Scholar 后再恢复。
- 引用数应明确标记数据来源和更新时间。

#### 论文内容页面

原来的三个页面调整为六个页面：

```text
Abstract
摘要
关键词
作者与单位
AI 解读
相关论文
```

标签采用内容宽度和横向滚动，不做六等分矩形布局。每次切换论文默认回到 `Abstract`。

**Abstract**：展示论文原始英文摘要。

- Markdown 和公式渲染。
- 文本可选择。
- 内容超出后滚动。
- 不进行两端对齐。
- 保持紧凑行距。

**摘要**：展示 DeepSeek 生成的中文翻译。界面只显示内容状态：

```text
生成中文摘要
正在生成...
生成失败，点击重试
```

不向用户显示「DeepSeek 中文翻译」「思考模式已关闭」「使用某某模型生成」等内部实现细节，它们不是阅读内容。

**关键词**：关键词必须来自论文内容，不能把 `cs.AI`、`cs.LG` 当作关键词。前期生成规则：

1. 使用标题和 Abstract 提取关键词。
2. AI 解读完成后，可以使用 PDF 全文重新生成更准确的关键词。
3. 每篇论文保存约 5–12 个关键词。
4. 关键词按重要程度排序。
5. 结果写入本地缓存。

示例：

```text
低秩适配
参数高效微调
冻结预训练权重
低秩矩阵分解
大语言模型
```

arXiv Subjects 和内容关键词必须分开存储。

**作者与单位**：独立展示：

- 完整作者列表。
- 第一作者、通讯作者等角色，有数据时才显示。
- 每位作者对应的单位。
- 单位缺失时不使用 `arXiv` 代替。
- 作者和单位的数据来源。
- 后续可以加入作者主页和同作者论文。

arXiv Atom 的单位数据不完整，缺失信息后续需要通过 OpenAlex、论文 PDF 或其他来源增强。

**AI 解读**：AI 解读固定回答六个问题：

- Q1：这篇论文试图解决什么问题？
- Q2：有哪些相关研究？
- Q3：论文如何解决这个问题？
- Q4：论文做了哪些实验？
- Q5：有什么可以进一步探索的点？
- Q6：总结一下论文的主要内容。

初始状态不自动生成，用户点击后才执行：

```text
生成 AI 解读
```

生成流程：

```text
下载 PDF
→ 提取正文
→ 清理页眉、页脚和参考文献噪声
→ 按章节或长度分块
→ 分块分析
→ 汇总为六个问题的结构化答案
→ 保存到本地缓存
```

DeepSeek 当前不一定支持直接上传 PDF，因此实现层面应先提取 PDF 文本，再分段发送给模型。缓存键至少包含：paperId、PDF 版本或文件哈希、提示词版本、模型版本、输出语言。论文更新或提示词结构改变后，可以判断旧缓存是否需要重新生成。

**相关论文**：暂时保留页面和空状态，真实检索后续实现。未来检索条件：论文标题语义、内容关键词、Abstract 向量、Subjects、作者关系、引用关系。第一阶段可以采用“标题 + 关键词”的语义检索，之后再加入全文向量和引用图谱。

#### 与 ChatPaper 的关系

AI 解读生成的六个答案作为该论文 ChatPaper 会话的默认背景信息：

```text
论文元数据
Abstract
关键词
六问 AI 解读
```

用户从论文页打开 AI 对话时：

- 自动关联当前论文。
- 不需要重新粘贴论文信息。
- AI 知道之前生成的六问答案。
- 用户可以继续追问实验、公式、局限性和相关工作。
- 默认上下文不作为聊天消息重复显示。

#### 缓存与云端路线

**当前单机阶段**，本地缓存：

- 中文摘要
- 内容关键词
- 六问 AI 解读
- PDF 提取结果
- 论文 AI 会话

所有能力按需生成，避免用户没有阅读意图时浪费 API 调用。

**后续云端阶段**，以稳定论文 ID 和 PDF 版本为键保存：

- 共享中文摘要
- 共享关键词
- 共享 AI 解读
- PDF 解析结果
- 语义向量

同一版本论文只需要生成一次，其他用户直接读取公共结果。

#### 开发顺序

1. 改造顶部频道栏和 `＋` 频道管理。（已完成；管理页为「主题 / 会议」Tab，对勾即添加状态，主题搜索与排序待目录扩大后恢复，见 `docs/workstreams/qodercn--feature-paper-channels/status.md`）
2. 建立 arXiv 主题与会议频道的数据模型。（已完成；主题模型与首批目录落地，会议频道模型保留、待真实数据源）
3. 将旧筛选按钮改为时间筛选。
4. 修正 source、venue、subject、publish time 和单位字段。（已完成；缓存 schema v2 迁移同步还原未知语义）
5. 移除引用数展示。（已完成核心目标：未知引用数不显示、生产链路不产生引用数；展示入口保留待可靠来源）
6. 将论文内容改成六个横向页面。（未开始；当前仍为「原文 / 中文解读 / 相关论文」三个 Tab，且 Tab 栏无横向滚动）
7. 完成中文摘要和内容关键词本地缓存。（部分完成：中文摘要按需生成 + 版本化缓存 + 失败重试已具备；摘要页仍显示「DeepSeek 中文翻译」等实现细节文案，待改为纯内容状态文案；内容关键词仅有实体与 OpenAlex 来源雏形，生成与独立缓存未实现）
8. 实现 PDF 下载、正文提取和六问 AI 解读。
9. 将 AI 解读接入论文 ChatPaper 默认上下文。（部分基础已具备：论文 AI 会话已并入聊天首页；六问结果作为默认上下文依赖第 8 条）
10. 最后实现相关论文语义检索和云端共享缓存。

#### 验收标准

- 添加或移除频道后，频道栏和本地配置同步更新。
- 每个频道查询、分页、错误状态和浏览位置互不污染。
- 时间筛选改变真实请求，离线时只使用匹配条件的缓存。
- 未知单位和未知引用数不会显示成虚假数据；内容关键词不包含仅用于分类的 arXiv 编号。
- 每篇论文默认进入 Abstract，六页切换无闪烁和高度跳变。
- AI 解读只在用户触发后下载和处理 PDF，失败可重试且不会破坏旧缓存。
- AI 解读完成后，新建论文聊天能读取六问结果作为默认上下文。

## 3. ChatPaper

### 3.1 当前能力

- 置顶主聊天和按论文创建的聊天。
- 论文讨论的 AI 会话与聊天首页共用同一会话仓储，聊天首页统一列出主聊天与论文会话，支持置顶与滑动删除。
- DeepSeek BYOK、流式回答、深度思考、联网搜索、停止和重试。
- Markdown、公式、代码块、来源展示和本地会话恢复。
- 会话置顶、删除和论文上下文管理。

### 3.2 当前边界

- API Key 由用户配置并保存在设备安全存储，公开构建不包含共享 Key。
- 会话和论文上下文保存在本地，不支持账号、跨设备同步或团队共享。
- 论文聊天目前主要使用论文元信息和摘要；完整 PDF 上下文依赖论文领域的 PDF 解析能力。

### 3.3 后续方向

1. 稳定流式 Markdown、公式、代码和来源的增量渲染。（基础已具备：增量节流渲染、公式纯文本降级、代码块复制、来源面板、未闭合语法稳定；持续打磨边界场景）
2. 明确主聊天、论文聊天和 AI 解读缓存之间的数据边界。
3. 接入 PDF 分块、可追溯引用和上下文裁剪。
4. 在提供平台共享额度前引入服务端代理、限流、审计和成本控制。
5. 为本地会话导出、备份和未来同步建立领域接口。
6. 增加会话级系统提示词、个性化偏好和可组合 Skills；先定义作用域、优先级、持久化与安全边界，再接入聊天运行时。

### 3.4 验收原则

- 输入区固定，不被消息内容或键盘异常挤压。
- 流式过程与最终内容布局稳定，不在结束时整体跳变。
- 代码块可复制，公式与 Markdown 失败时仍有可读纯文本降级。
- 每个会话的上下文、思考开关和联网状态行为明确且可恢复。

## 4. 我的

### 4.1 当前能力

- 默认收藏与自定义收藏分组。
- 阅读历史、稍后阅读、主题设置和本地数据管理。
- DeepSeek API Key 验证、保存、替换和删除。
- 应用版本、隐私说明和开源许可入口。

### 4.2 当前边界

- 用户资料、收藏、历史和设置只保存在当前设备。
- 不提供登录、云同步、私信、通知或公开主页。
- 清理业务数据不得隐式删除 DeepSeek Key；敏感操作必须二次确认。

### 4.3 后续方向

1. 完善收藏分组的重命名、排序、批量移动和删除保护。（现状：重命名与带二次确认的删除已实现，默认分组受保护；分组排序、批量移动未实现，删除分组会一并移除组内收藏关系）
2. 增加个人研究数据导出、导入与备份恢复能力。
3. 统一数据占用统计、分类清理和迁移失败恢复。
4. 在账号体系获得明确需求后，再通过领域接口接入跨设备同步。

### 4.4 验收原则

- 所有数据管理操作明确展示影响范围并可验证结果。
- 收藏、历史和稍后阅读在应用重启后保持一致。
- 密钥只显示掩码，不进入日志、文档、源码或普通本地数据文件。
- 未实现的账号或社区能力不以无行为入口出现在生产导航中。
